# What changed on 2026-11-19 and 2026-11-20

A record for anyone who was following the repo before this and wants to know what happened since. [HISTORY.md](../HISTORY.md) holds the decisions, one entry each. This file is the story in order: what was asked, what was found, what was changed, and what was measured. [open-items.md](open-items.md) is what is still undone.

All of it is on the `test` branch. `trunk` was not touched and is behind.

## Where the work started

The first read of the repo was of a stale checkout. It saw `trunk` and one older branch, and described an app with no relay, no recovery, and no sync. The real work was on `test`, about 35,000 lines further on. Everything below was done against `test`. The first performance numbers were thrown away and taken again on the right code.

State at the start, from [ROADMAP.md](../ROADMAP.md): notes, a second folder, one 1:1 through the loopback relay, HPKE sealing, recovery from the phrase, a SQLCipher search index, and an Iced window called Aerodash. Spec 05 unwritten. `just ci` was already failing on lints that predated this work.

## What was measured

All of these were measured, not guessed. The probes were throwaway programs and are not in the repo. The measuring method is in [TESTING.md](TESTING.md).

**Saving, release build, a thousand notes of about 2 KB.**

| | Before | After |
|:--|--:|--:|
| A window save | 331 ms | 30 ms |
| The reload after it | 157 ms | 2 ms |
| Opening a notebook | 175 ms | 0.2 ms |
| Adding a note | 119 ms | 16 ms |
| The first search after a change | 1,666 ms | 65 ms |

**Typing, dev build, what `cargo run` runs.**

| Note size | Before: a key + `follow` | After: a key + `follow` + the view |
|--:|--:|--:|
| 2.5 KB | about 7 ms | 0.6 ms |
| 13 KB | about 36 ms | 3 ms |
| 51 KB | about 130 ms | 12 ms |
| 194 KB | about 520 ms | 46 ms |

The "before" figures leave out the cost of building the view, which was measured after, so the real improvement is larger than the table shows.
The causes, in order of size: shaping every paragraph again to wrap it on every update (0.9 ms each in an unoptimized build), a full re-parse of the page on every key, and `follow` measuring every line. A smaller one was `line_start`, which rescanned from the top for every line.

**The flaky test.** `restored_folder_writes_back` failed 3 runs in 8 on the unchanged tip. After the fix it passed 24 in 24, and the sync suite passed 10 in 10.

**Spelling.** On the repo's own docs the old checker flagged 757 distinct words and the new one 67, most of them real jargon. Of the 5,000 most common English words, one was missing.

## What was found that nobody asked about

- Two separate bugs hid behind the flaky test. The first was the merge order: a new device's first note was ready before its enrollment and was dropped for good. The second was real and separate: a sync overwrote writes made while it waited. A guess that the second was the cause of the flake was wrong. The guess was disproved by running the test many times, and the real cause was found by reading `apply_ready`.
- The write path was O(N) in several places and threw its cache away after every save. The window opened a new `Notebook` for every save, so a cache inside one `Notebook` would not have helped. That is why the cache is shared by weak reference.
- The first fix for the retry loops, eight immediate tries, failed every time once the build was fast. The lock is not first come, first served.

## Mistakes made and corrected

Kept here so they are not repeated.

- Reading the wrong branch first. Check `git branch -a` and `git fetch` before describing the app.
- Adding a scroll message for every wheel tick made scrolling slow, because each one ran `update`, rebuilt the whole view, and restarted a subscription. A scroll must never go through `update`. Now a wheel tick is one atomic store.
- A commit went in with a lint error, because the commit was chained after the lint instead of gated on it. It was fixed before pushing. Gate commits on the lint.
- A first guess that unconditional writers caused the flaky test was wrong.

## Found while writing this

- "Erase this notebook" left the personal dictionary's words in memory, so they would have been written back into the next notebook. Fixed, with a test.
- The dictionary file, like `names`, `profile`, and `seen`, is plain text beside the sealed log. [THREAT_MODEL.md](../THREAT_MODEL.md) now says so.
- `crates/ambient-cli` had no `AGENTS.md`. It does now.
- The decision to make a note from a not-yet-enrolled signer wait is a protocol-behavior change and had a spec edit and no ADR. [ADR-0006](adr/0006-wait-for-enrollment.md) is written as Proposed.

## What was not checked

- Nothing in the window was looked at. The environment had no display. Every window behavior here is covered by tests of the state and the pure functions, not by eyes.
- `just`, `cargo-nextest`, and `cargo-deny` were not installed where this was done. `just deny` was not run. No dependency was added. The equivalent `cargo` commands were run: format, clippy with warnings denied on the whole workspace, tests, docs with warnings denied, and the wasm check.
- GitHub Actions was not looked at.
